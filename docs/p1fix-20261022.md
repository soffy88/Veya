## 二、改动

### P1-1 默认 LLM 链路必超时

根因（与验收报告一致，本轮补齐了最后一环）：前 3 层各自吃满超时，且**每轮重试 3 次**，
第 4 层 OpenRouter 虽可用却永远轮不到。逐层实测：`opencode-go` 401（1.0 s）、
`veya-gw` 连接超时（容器内经 docker 网桥到宿主 8791 被宿主 ufw 丢弃）、
`veya-nim` 无 key / 子模型 404 / ReadTimeout。

`veya/obase/llm.py`：

1. **每层独立短超时**：新增 `VEYA_TIER_TIMEOUT_S`（默认 18 s），并按
   `connect_timeout` / `read_timeout` 拆给 httpx；`llm_call` 接受这两个参数。
   池内 `timeout` 字段从 `45`（veya-gw/workbuddy）与 `30`（veya-nim）统一收到 18。
2. **整层 deadline**：单请求超时管不住嵌套代理（`veya-nim` 一次调用内部串多个 NIM 模型），
   因此每次 tier 调用外包一层 `asyncio.wait_for`，deadline = 该层超时。
3. **401/403 与连接拒绝立即熔断**：`_fast_break()` 分类 `auth` / `connect`，
   命中后写 breaker（auth 10 min、connect 2 min）并立刻跳过该层，不重试、不等满。
4. **缺 key 直接摘除**：`_pool_candidate_has_key()` 在入池前过滤，无凭据的 provider
   不进入池（`veya-nim` 以 key pool 大小判定）。
5. **同轮不再重付死层**：本轮内已超时 / 已返回 `error=True` 的层加入 `failed_this_turn`，
   后续重试轮跳过；空回复仍可重试（通常是瞬时）。
6. **整池时间预算**：`VEYA_BRAIN_TURN_BUDGET_S`（默认 100 s），到点停止整轮重试，
   退避等待前也先检查预算。
7. **breaker 重探限频**：`VEYA_BRAIN_REPROBE_INTERVAL_S`（默认 60 s）。原 B1 语义是
   每次调用都重探一次已熔断层——多轮对话里每轮都要重付一次死层超时，这是修复后
   仍接近 100 s 的原因。

`veya/obase/brain_breaker.py`：新增 `note_provider_break(provider, kind)`
（`auth` / `connect` / `nested` 三档 cooldown），导出到 `__all__`。

**配置层摘除（已记录备份路径）**：宿主 ufw 丢弃 docker 网桥到 8791 的流量，
容器内 `host.docker.internal:8791` 与 `127.0.0.1:8791` 均不可达，
因此该层在本部署里是必然 miss。已按验收建议在配置层摘除：

- 文件：`/home/soffy/.config/veya/backend-override.yml`
- 新增：`VEYA_GATEWAY_POOL_DISABLED: '1'`（`_veya_gateway_candidates()` 的既有开关）
- 备份：`/home/soffy/wim/p1fix/backend-override.yml.backup-p1fix-20261022T024254Z`
  与 `/home/soffy/.config/veya/backend-override.yml.bak-p1fix-gw-20261022T030422Z`

代码里的 veya-gw 层保留（宿主上它仍是快路径），靠 1/3 的机制把 miss 压到毫秒级。

### P1-2 `search_tools` 截断成非法 JSON

`server/tool_registry.py`：

- 新增 `_SEARCH_TOOLS_RESULT_CHARS = 16000`、`_search_tools_render()`，
  在预算内装配 payload，不再依赖 `_to_str` 的字符硬截断。
- 装配顺序：全量 schema 装得下 → 原样返回；装不下 → 从尾部减条数（`loaded` 仍记全量）；
  仍装不下 → 紧凑 schema（`name` + `description` + 必填参数与类型）；
  再装不下 → 仅 `name` + 按词边界截断的 description。**输出始终是合法 JSON**，
  且至少保留一条命中。
- 新增 `_compact_tool_schema()`（description 上限 1200 字符）、
  `_truncate_on_word()`、`_search_tools_payload_fits()`。

### P3-4 headless 失败状态

`platform/3O/omodul/omodul/automata.py`（submodule，分支
`fix/acceptance-p1-headless-status`，commit `873443c`）：
`_run_headless_mission` 在记录结果前判断 `HEADLESS FAILED:` 前缀，命中置
`status="failed"`。原先只有抛异常才置 failed，runner 把失败吞成字符串时会被漏报。

1. **`browser_run` 仍不可用**（P2-2，镜像缺 Playwright 浏览器）。它每轮消耗一次
   工具失败与一次 replan，是 45.2 s 里占比最大的非 LLM 开销。本轮未修，因为它需要
   镜像层补浏览器或改后端选择，属于另一项改动。
2. **veya-nim 层仍会偶发 ReadTimeout**，但已被整层 deadline 与同轮跳过限住；
   宿主侧 key pool 有 4 把 key，部分模型 id 404 是上游目录变更。
3. **`search_tools` 在极端长 schema 下会退化为「name + 截断 description」**，
   此时模型需再直接调用工具才能拿到完整参数（惰性加载本身会补齐）。
4. 本轮的 P1-1 改动触及冻结主链路的 LLM 层与兜底逻辑；按用户授权执行，
   行为面只收紧超时与跳过，未改默认 provider/model 与工具面。
5. `test_master_tools.py` 的 6 个失败、`test_coding_sandbox_profiles.py` 的 1 个失败、
   `test_llm.py` 的 1 个失败、`tool_registry.py` 的 4 条 ruff 报错均为 **main 上既有问题**，
   本轮未改动、未掩盖。
