# NANO-W6: Tiered approvals + cross-device @runner routing with approval relay
Branch feat/nano-approvals-devices. Test file tests/test_nano_w6_approvals.py.
1. Approval gates: before destructive/outbound/payment-like tool calls (delete files outside workspace, send message/email, git push, spend), GoalRun pauses with an approval request. User answers: allow once / allow for this session / always allow (per user+tool+scope pattern) / deny. Persist "always" grants per user (SQLite under existing store conventions), list+revoke via REST. Human handoff: tool may request "user must do this step" (login/captcha/code) -> paused state with Done/Cancel resume.
2. Approval relay: pending approvals fire a Web Push (P5) to the user's subscribed devices; the push opens /approvals/<id> in the PWA; answering resumes the run on whichever runner holds it.
3. @runner routing: a chat message starting with `@<runner-name> ...` (case-insensitive, matches P6 runner registry names/aliases) forwards the turn to that runner; unknown name -> helpful error listing runners. Approvals from that remote run come back to the originating user's devices.
4. UI: approvals inbox page + inline approval card in chat; settings page listing "always" grants with revoke.
Flag VEYA_APPROVAL_GATES (default off; when off, behaviour unchanged).
