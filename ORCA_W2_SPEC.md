1. Hand off. POST /api/v1/sessions/{id}/handoff {target_backend, target_model?, mode: "focused"|"full", note?}. Creates a NEW session (forked_from=id, kind=handoff), original untouched. focused (default): a generated brief = goal, constraints/rules the user stated, current progress, files touched, open todos, current worktree path, how to read older history; full: whole transcript (warn in response: slower, costs context). The brief is editable: GET preview first, then confirm. Target may be another backend (e.g. Codex continues Claude's work). Delivery state must be honest: "delivered" only when the target session's first turn actually started, else "unconfirmed" + a copyable prompt field.
2. Fork polish. Fork from a session gives an editable draft summary for the new session (same brief generator), lives beside the original; delete fork cleans up its worktree if it had one.
3. Session search. Full-text search over all the current user's session transcripts (SQLite FTS5 index maintained on write, rebuild command for existing data), filters by bot/backend/date, results with snippet + jump link. If runners are configured (server/bot_team/runners.py), optional federated query to runners with timeout; failures don't break local results. REST GET /api/v1/sessions/search?q=.
UI (apps/web): session context menu items "Fork", "Hand off to another agent" (dialog with mode + agent list + editable brief + copy-prompt fallback), and a search box in the session list.
Tests: brief generation focused vs full, original unchanged, delivery state, FTS index + search + user isolation, federated failure tolerance with fake transport.
