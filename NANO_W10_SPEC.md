# NANO-W10: always-on agent ergonomics (from Lee Robinson CS146S lecture "How always-on, proactive agents work")

1. Turn queue with priority + coalescing: per-bot/per-conversation turn queue on top of the EXISTING turn path (server/bot_team/turns.py, async_turns.py) and GoalRun — not a new scheduler. Priorities: direct user message > group/@mention > channel inbound > routine/background. A direct user message arriving mid-turn is delivered as a steer at the next safe point (reuse W6 K delivered/started/unconfirmed receipts) instead of waiting; messages arriving within a short window (default 2s, configurable) while a turn is pending are coalesced into one turn. Idempotency key per inbound message so client retries never create duplicate turns. oskill turn_priority (pure ordering/coalescing rules); omodul turn_intake; state in existing stores.
2. Wake router + "worth bugging the user?" policy: all wake sources (user, routine clock, W9 event triggers, W7 channels, runner results, sub-agent completion) pass through one intake that dedupes (compute_fingerprint_for) and classifies the outcome as: reply now / batch into digest / silent (log only) / emoji-ack. Policy inputs: user-directed vs background, novelty, urgency, user quiet hours setting, per-bot notification level. Push (P5) and channels (W7) only fire for "reply now"; digests reuse W7 morning feed. Implement via existing oservi triage(on_signal)/alerter engines; decision_trail pillar on.
3. Auto-review of commands: before a shell command or side-effecting tool runs (ActionGateway hook), a separate reviewer model call (via ModelRouter availability path, injected LLMCaller) classifies allow / ask human / block with a reason, given the command, the originating instruction, and whether any untrusted input (email, web, channel message — mark provenance via firewall.sanitize) influenced it. "Ask human" escalates through the existing SideEffectLedger approval. Human-only categories from W6 L (DB migrations, payments/secrets, production) always go to the human regardless. oskill command_review (prompt build + parse, pure); omodul auto_review; decision_trail + cost pillars. Flag VEYA_AUTO_REVIEW.
4. Prompt-cache discipline: assemble the model prompt in fixed-order hashed sections (system, tool defs, core memory, ...then conversation); the tool set is frozen for the duration of a turn (tool_search results appended as messages, never by mutating the tool list); record per-call cached vs uncached input tokens in existing usage events and expose cache-hit rate on the performance route. Prewarm: when the client signals typing (lightweight endpoint, debounced), build and optionally send a cache-warming request when the provider supports it. Proactive compaction: when a conversation exceeds a threshold and goes idle while the provider cache window is still warm (configurable, default 5 min), compact it immediately (reuse existing compact_session logic) so the next turn starts from the summary. Flag VEYA_PROMPT_CACHE.
